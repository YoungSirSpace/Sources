# 友元

根据数据封装的要求，类中定义的数据成员不能在外界直接访问，必须要通过类中定义的public成员函数来访问。

为了提高在类的外部对类的数据成员的访问效率，在C++中，可以指定某些与一个类密切相关的、又不适合作为该类成员的程序实体**直接访问该类的非public成员**，这些程序实体称为该类的友元。

友元机制允许特定的函数或类访问另一个类的 `private`（私有）和 `protected`（保护）成员。这在某些高耦合的底层设计中是必不可少的。

---

## 友元的几种形态

**A. 友元函数 (Friend Function)**

一个普通的全局函数，被类声明为“好朋友”，从而获得访问权限。

```cpp
class Box {
private:
    double width;

public:
    Box(double w) : width(w) {}

    // 声明全局函数 printWidth 是我的友元
    friend void printWidth(const Box& b); // 语法：friend
};

// 实现时不需要加 Box::，也不需要加 friend 关键字
void printWidth(const Box& b) {
    // 它可以直接访问私有成员 width
    std::cout << "Width of box: " << b.width << std::endl;
}
```

**B. 友元类 (Friend Class)**

类 A 可以声明类 B 是它的友元。此时，类 B 的**所有成员函数**都可以访问类 A 的**私有**数据。

```cpp
class Engine {
private:
    int horsePower = 500;
    friend class Car; // 声明 Car 为友元类
};

class Car {
public:
    void showEnginePower(const Engine& e) {
        // 直接访问 Engine 的私有成员
        std::cout << "Engine Power: " << e.horsePower << " HP" << std::endl;
    }
};
```

注意，关于友元，有三个非常重要的原则，可以总结为：**“单向、不传递、不继承”**。

- 友元关系是单向的：如果 A 是 B 的友元，并不意味着 B 是 A 的友元。

- 友元关系不能传递：如果 A 是 B 的友元，B 是 C 的友元，不能推导出 A 是 C 的友元。

- 友元关系不能继承：基类的友元对派生类没有特殊访问权限；同理，派生类的友元也不能访问基类。

以及，友元要慎用、少用。如果一个类有太多的友元，通常意味着你的模块划分出了问题（耦合度过高）。
