# 聚合/组合

**继承不是代码复用的唯一方式。**

在面向对象程序设计中，有些代码复用不宜用继承来实现：继承体现了类之间在概念上的一般与特殊关系（is-a-kind-of）。如果两个类之间没有这个关系，纯粹是为了代码复用而用继承把它们关联起来，这样会造成概念上的混乱。

例如，`Plane`类复用`Engine`类的功能就不宜用继承来实现。

类之间除了继承关系外，还存在一种整体与部分的关系（is-a-part-of），即一个类的对象包含了另一个类的对象。例如，“飞机”类与“发动机”类之间就是整体与部分的关系。

类之间的整体与部分的关系可以是，**聚合**（aggregation）关系，以及**组合**（composition）关系。

---

## 聚合 (Aggregation)

在聚合关系中，被包含的对象与包含它的对象**独立**创建和消亡，被包含的对象可以脱离包含它的对象独立存在。聚合是一种弱依赖关系。

聚合类的成员对象一般是采用对象指针表示，用于指向被包含的成员对象，被包含的成员对象在外部创建，然后加入进来。

比如研发部和员工的关系。

```cpp
class Employee {
    string name;
public:
    Employee(string n) : name(n) {}
};

class Department {
private:
    Employee* member; // 聚合：只存指针，Employee在外面活着
public:
    void addMember(Employee* e) { member = e; }
};
```

## 组合 (Composition)

在组合关系中，被包含的对象**随**包含它的对象创建和消亡，被包含的对象**不能脱离**包含它的对象独立存在。部分对象通常在整体类的构造函数中创建，在析构函数中销毁。

组合类的成员对象一般直接是对象，有时也可以采用对象指针表示，但不管是什么表示形式，成员对象一定是**在组合类对象内部创建并随着组合类对象消亡**。

比如人体和心脏的关系。

```cpp
class Heart {
public:
    void beat() { /* 咚咚咚 */ }
};

class Human {
private:
    Heart myHeart; // 组合：Heart对象直接作为成员，生死与共
public:
    void live() { myHeart.beat(); }
};
```

---

“优先使用组合，而不是继承”（Favor composition over inheritance）。

- 降低耦合： 继承会暴露父类的细节（白盒复用），而组合/聚合只通过接口交互（黑盒复用）。

- 灵活性： 聚合允许你在程序运行过程中，动态地更换“部分”。

- 内存管理： 组合的内存管理非常简单（自动回收）；聚合则需要你小心处理指针，防止出现“部门解散了，但员工也没处去（内存泄漏）”或者“员工走了，部门还在找他（野指针）”的情况。
